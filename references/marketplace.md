# 魔方商城打包、复审与交付

## 授权代码插入报错

1. 对照商城驳回原文、报错行、送审 ZIP 的入口和官方生成文件。确认插件类名及官方约定的 `<类名>idcsmartauthorize()` 名称和签名。若能取得实际注入结果，优先检查其命名空间、类别名、方法边界和插入点。
2. 如果语法错误集中在入口的分组导入或授权方法边界，可尝试改用 `logic\Schema::install()` 这样的命名空间相对引用或完全限定类名。保留原授权方法公开签名，将占位方法放在类体开头并采用标准多行方法。将改动集中在商城处理的入口文件，并保留现有授权行为。
3. 对送审原包和实际注入产物分别使用目标 PHP 执行语法检查，检查正常加载和授权拒绝路径。若没有官方产物，在临时副本模拟授权方法替换或安装检查插入，给出模拟覆盖范围。模拟代码和返回值仅用于临时测试；线上授权流程由实际官方产物验证。

## 构建与核验商城 ZIP

1. 根据用户已指定的版本和项目约定准备候选源码，核对插件元信息、对外说明与必要的前端资源标识。若版本待定，先完成开发验证或明确标记内部候选。保留原包、哈希、标签、发布历史和真实升级基线。
2. 优先使用插件仓库现有构建器。新插件还没有构建器时，按运行文件清单复制到独立暂存目录，再将该模块要求的安装目录打成 ZIP。常规 addon 的 ZIP 顶层是插件标识目录，例如 `example_plugin/ExamplePlugin.php`。保留生产所需的依赖、静态资源、许可和要求随包的说明。排除整站、平台及主题补丁、站点配置、测试、数据库、开发依赖、原始日志、凭据及私有维护资料。
3. 检查 ZIP 文件清单与候选暂存源码逐文件一致，计算 SHA-256。按 [测试验收](acceptance.md) 用实际包安装和运行对应门禁。重新生成的 ZIP 应记录新哈希。

[通用 ZIP 检查脚本](../scripts/check_zip.py) 只读取包，检查目录、入口、ZIP CRC，并用指定 PHP 逐个做语法检查。它适用于单一插件根目录的交付结构。元信息、依赖、私有内容、授权注入和安装能力仍按各自环节验证。用实际插件标识、入口文件名和目标 PHP CLI 替换示例值。

```bash
python3 /path/to/v10-plugin-marketplace/scripts/check_zip.py /path/to/candidate.zip \
  --root example_plugin --entry ExamplePlugin.php --php /path/to/target/php
```

## 商品资料与交付

- 商品说明用运营语言描述能解决的问题、后台控制项、会员使用路径、实际支持版本与主题、依赖、安装步骤和使用限制。版本说明按实际适用的新增、优化、修复整理，复审时可指出授权注入兼容改动。
- 商品截图与图文教程使用虚构数据并单独交付。公开展示仓库按用户指定的范围上传说明、步骤和截图；商业插件源码、安装 ZIP、源码补丁及内部证明材料保存在各自授权的交付位置。
- 下载链接使用已经确认的最终 ZIP。用户要求宝塔外链时，分享单个文件并实际下载对比 SHA-256，说明北京时间到期时间。商城提交、更新商品或 GitHub 发布按本轮授权执行，收件或审核结果以平台反馈为准。
