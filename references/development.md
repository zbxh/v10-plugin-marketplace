# 插件开发

## 从目标 V10 核对入口

- 在目标 V10 用 `app/common.php` 的 `get_plugin_class()` 确认模块、目录、命名空间、入口文件、类名及大小写。常规 addon 采用 `public/plugins/addon/example_plugin/ExamplePlugin.php`、`addon\example_plugin\ExamplePlugin` 和 `app\common\lib\Plugin`。其 `$info` 需要 `name`、`title`、`description`、`author`、`version`。维护已有插件时沿用原作者署名。
- server 产品模块先看目标版本的模块调用和已维护的同型插件，核对 `metaData()`、商品配置、定价、开通、续费和辅助接口。网关、通知等其他模块同样以各自契约为准。
- 追溯原生调用点，读参数、返回约定、调用顺序和失败行为。后台和会员独立使用平台鉴权，写操作校验具体权限或资源归属。导航、按钮、路由与 `auth.php` 要对应。addon 安装可能反射公共方法生成钩子，保持内部工具方法非公开，自定义钩子同步时核对重复登记和启停状态。
- 新业务表、迁移、配置、页面资源和第三方适配随插件交付。前台通过目标版本有效的会员区或购物车扩展点接入，在插件内适配官方主题和用户指定的第三方主题。按实际使用路径验证账单、收银台、结算等入口，识别 Vue 或 React 的挂载时机、弹层和异步刷新，避免重复挂载及误影响原生流程。

## 后台 UI 实现

- 新增或调整插件后台页面前，先找目标 V10 版本里用途相近的官方后台页面，核对模板结构、组件、尺寸属性、布局类和实际加载的公共样式。表单、筛选栏、页签、表格、分页、操作按钮和弹窗按对应官方页面的用法实现。
- 直接复用后台已加载的官方组件和样式类。统一同类同规格控件的尺寸属性，同排控件沿用官方布局、对齐、间距和换行方式。V10 已有对应组件或布局时，禁止用插件 CSS 重写其外观和尺寸。官方没有对应方式时，只补业务所需的样式，将选择器限定在插件页面内。
- 样式和模板改动留在插件目录。实现后按 [后台 UI 视觉验收](acceptance.md#后台-ui-视觉验收) 核对官方参照和插件渲染结果。

## 生命周期和业务边界

- 确认安装、升级、启停和卸载的数据承诺。目标 V10 可能在平台事务内执行 `upgrade()`，而 MySQL DDL 会隐式提交。识别事务边界，按现有维护方案安排事务外迁移，例如目标版本确认可用的提交后事件。迁移应可重试，实际失败要能按正常流程恢复。验收时检查配置、字段、唯一索引、角色权限、钩子、通知动作与缓存。新增敏感权限默认按最小授权处理。
- 跨订单、退款、任务或通知的功能先对齐状态与发生顺序。确保回调重复、任务重试或并发下只处理一次，保留历史订单记录与业务快照。涉及金额时对照订单明细、实付、退款、开票、收益等实际受影响的口径。
- 邮件、短信和供应商通知通过平台约定的动作或接口衔接。测试结果按实际到达的阶段记录，例如动作登记、已入队、渠道接收、送达。其他插件负责的渠道或履约，以原生调用边界为验收范围。
- 运营日志用业务动作、对象、结果和可处理原因表达。技术异常留在诊断日志，可用关联编号定位。运营页面提供平台已有的筛选、分页和权限体验，按本轮需求核对直接跳页或导出。
