# 安装、升级和运营验收

## 纯净安装

1. 使用用户指定的隔离测试站。需要新环境时，从与目标一致的官方 V10 安装包搭建，使用独立数据库、站点及虚构账号，如需特定依赖再按正常流程安装已授权的插件。记录 V10、PHP、主题、依赖版本和安装包 SHA-256。遇到既有站的名称、根目录或程序维护问题，先核对当前状态。
2. 按最终 ZIP 的实际结构解压到对应模块目录，再走该模块的原生后台安装入口。普通 addon 在 V10 10.7.4 中可从后台「应用列表」安装，具体以目标版本为准。所需操作应与随包安装说明一致。验证列表版本、安装登记、基础设置、正常刷新和插件重载。
3. 使用普通管理员角色和测试会员操作正常页面。打开所需开关，用不同规则覆盖主要分支，检查成功、拒绝、空数据、边界值及失败提示。相应角色的按钮、页面和服务端权限都要核对。准备测试数据可用平台后台或隔离夹具，运营人员日常使用应能只靠后台。
4. 验收候选 ZIP 时记录其 SHA-256，核对实际安装文件与包内容。重新打包后按改动范围复验最终包，复用旧结果时说明哪些内容和环境已对照一致。需要证明插件独立交付时，对照核心或主题文件基线。

## 已发布版本升级

- 从插件约定的真实已交付旧包建立旧结构和旧数据，校验旧包哈希，再用候选包走目标 V10 的有效升级入口。保留必要的配置、业务历史和角色权限。覆盖关键迁移失败后重试、重复执行、停用后恢复等相关场景。
- V10 10.7.4 的原生更新会比较版本并要求新版更高。同版本修复应声明测试过的交付路径，避免将手工替换描述成系统自动升级。首发可记录升级不适用。
- 执行该插件已有的发布门禁并保存实际结果。静态语法、脚本检查、真实安装、升级和外部授权分别记录。门禁失败或环境缺失时写明受影响的验收项。

## 功能和主题

- 按业务整理操作路径和数据结果。以订单抵扣类插件为例，可检查适用商品、有效期、优惠叠加、金额选择、取消、退款与日志。订单净额、开票与收益在原生入口核对。通知若只需确认触发，可对照邮件和短信动作及对应事件证据。
- 根据要求在目标官方桌面主题、适用的官方移动主题及 CRA1 分别登录测试。在真实页面核对入口、布局、交互、金额和提交结果。组件用例、模拟请求和完整运营路径分别标记；有差异时记录主题版本和触发页面。
- 使用测试支付、隔离通知动作或供应商测试端点。未安排真实外发或履约时，通过测试桩、队列、调度或本地记录核对调用。展示截图从已验证路径采集并清理敏感信息，原始诊断、会话状态和凭据保存在本地。
